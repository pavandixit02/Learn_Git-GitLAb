1. What is a Git Branch?

Git Branch ek independent line of development hoti hai jisme tum existing project ke codebase ko affect kiye bina changes develop kar sakte ho.

Simple words mein: Branch = Code ke development ka separate path.

Real-Life Analogy:

Imagine karo tum ek book likh rahe ho.

Main book = main branch
New chapter ka experiment = feature branch

Tum experiment kar sakte ho without original book ko directly change kiye.

Default Branch

Git repository mein commonly main branch default branch ke roop mein use hoti hai.

Kuch older repositories mein master naam bhi mil sakta hai.

2. Branches ki Need Kyu Hoti Hai?

Agar multiple developers directly main branch par kaam karein to code stability aur collaboration difficult ho sakti hai.

Branches ke Benefits

Isolation

New feature ko separate environment mein develop kar sakte ho.

Safety

Main branch ko directly affect kiye bina changes test kar sakte ho.

Collaboration

Multiple developers parallel development kar sakte hain.

Code Review

Feature branch ko Merge Request ke through review kar sakte ho.

3. Branch Structure

Example project:

main │ ├── feature-login │ ├── feature-payment │ ├── feature-dashboard │ └── bugfix-login

Yahan:

  • main = stable/main development line
  • feature-login = Login feature
  • feature-payment = Payment feature
  • bugfix-login = Login bug fix
Branch names meaningful rakho.

Good: feature-login
feature-payment

4. Existing Branches Check Karna

Local Branches

All Local + Remote Branches

Current Branch Check

Good Habit: Kaam start karne se pehle check karo ki tum currently kis branch par ho.

5. Branch Create Karna

Method 1 — Create Branch Only

git branch feature-login

Ye branch create karega, lekin automatically us branch par switch nahi karega.

Method 2 — Create + Switch

git switch -c feature-login

Ye command:

  • New branch create karti hai.
  • Immediately new branch par switch karti hai.
Recommended beginner command:

git switch -c feature-login

Older Git Syntax

git checkout -b feature-login

Ye bhi create + switch karta hai.

6. Branch Switch Karna

Existing branch par switch karne ke liye:

git switch main

Ya:

git switch feature-login

Older Command

git checkout feature-login
Branch switch karne se pehle uncommitted changes ko check karna good practice hai.

Use: git status

8. Branch ko GitLab par Push Karna

Local branch create karne ke baad usko GitLab remote repository par push kar sakte ho.

Command

git push -u origin feature-login

Yahan:

  • git push = local commits remote par bhejna
  • -u = upstream tracking set karna
  • origin = remote repository
  • feature-login = branch name

After First Push

Upstream set hone ke baad future changes ke liye:

git push

9. GitLab Merge Request

GitLab mein branch ke changes ko review aur target branch mein merge karne ke liye Merge Request (MR) use hota hai.

Typical Flow

feature-login
→
Push
→
Merge Request
→
Code Review
→
Merge
→
main

Merge Request mein kya hota hai?

  • Source branch select karna.
  • Target branch select karna.
  • Title add karna.
  • Description add karna.
  • Code changes review karna.
  • Reviewers/approvers assign karna, where configured.
  • CI/CD pipeline results check karna.
  • Approval ke baad merge karna.
Example:

Source: feature-login
Target: main

Meaning: "Mere login feature ke changes ko main branch mein merge karne ke liye review karo."

10. Branch Merge Karna

Merge ka purpose ek branch ke changes ko doosri branch mein integrate karna hai.

Example

main │ ├── feature-login │ │ │ └── Login changes │ └──────────────→ Merge into main

Step 1 — Main Branch par Switch

git switch main

Step 2 — Latest Main Changes Get Karo

git pull origin main

Step 3 — Feature Branch Merge Karo

git merge feature-login

Step 4 — Main ko GitLab par Push Karo

git push origin main
Complete local merge workflow:

git switch main
git pull origin main
git merge feature-login
git push origin main

11. Fast-Forward Merge

Agar main branch par feature branch create hone ke baad koi new commit nahi hua aur history linear hai, Git fast-forward merge kar sakta hai.

Before: main | A | B | feature | C | D After Fast-Forward: main | A | B | C | D

Is case mein Git ko separate merge commit ki zarurat nahi pad sakti.

12. Three-Way Merge

Agar main aur feature branch dono independently change ho gaye hain, Git ko common ancestor ke basis par changes integrate karne pad sakte hain.

B / \ C D | | E F \ / M M = Merge Commit

Is situation mein merge commit create ho sakta hai, depending on history and merge strategy.

13. Merge Conflict

Merge conflict tab ho sakta hai jab Git automatically determine nahi kar pata ki conflicting changes ko kaise combine karna hai.

Example

main:

Welcome to GitLab

feature:

Welcome to DevOps

Git ko decide karna hai ki final version kya hona chahiye.

Conflict Workflow

Merge
→
Conflict
→
Edit File
→
git add
→
Commit

Step 1 — Conflict Check

git status

Step 2 — Conflicting File Open Karo

File mein conflict markers appear ho sakte hain: 


<<<<<<< HEAD
Current branch code
=======
Incoming branch code
>>>>>>> feature-login

Step 3 — Correct Code Select Karo

Final desired code rakho aur conflict markers remove karo.

Step 4 — Stage

git add .

Step 5 — Complete Merge

git commit

Step 6 — Push

git push origin main

14. Merge Abort Karna

Agar merge conflict ke beech mein tum merge process cancel karna chahte ho:

git merge --abort
Ye command merge conflict state se bahar aane ke liye use ki ja sakti hai jab merge operation active ho.

15. Branch Delete Karna

Local Branch Delete

git branch -d feature-login

Ye safely merged branch ko delete karne ke liye commonly use hota hai.

Force Delete

git branch -D feature-login
Warning: -D force deletion karta hai. Unmerged changes wali branch delete karte waqt carefully use karo.

Remote Branch Delete

git push origin --delete feature-login

21. Branch vs Separate Project

Branch Separate Project
Same repository ke andar hoti hai. Separate repository hoti hai.
Feature development ke liye useful. Completely different project ke liye useful.
Same Git history share karti hai. Separate Git history hoti hai.
Merge Request se main branch mein merge ho sakti hai. Normally independent lifecycle hota hai.

22. Common Branching Mistakes

Mistake 1

Directly main branch par har feature develop karna.

Mistake 2

Branch create karne ke baad branch check na karna.

Mistake 3

Wrong branch par commit kar dena.

Mistake 4

Remote push karne se pehle remote URL check na karna.

Mistake 5

Merge conflict ko samjhe bina random code delete karna.

Mistake 6

Unmerged branch ko force delete kar dena.

Best Habit:

Har important operation se pehle:

git status
git branch --show-current
git remote -v
