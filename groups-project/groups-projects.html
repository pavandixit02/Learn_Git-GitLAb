1. What is a GitLab Group?

GitLab Group ek organizational container hai jisme tum related projects ko ek common place par organize aur manage kar sakte ho.

Simple words mein: Group = Multiple related projects ko organize karne ka container.

Real-Life Analogy:

Socho ek company hai:

Company → Group
Development Department → Subgroup
Project A, Project B, Project C → Projects

Group ki zarurat kyu hoti hai?

  • Multiple projects ko organize karne ke liye.
  • Team members ke access ko manage karne ke liye.
  • Related repositories ko ek common namespace mein rakhne ke liye.
  • Team collaboration ko simplify karne ke liye.
  • Large organization ke projects ko structured way mein manage karne ke liye.

Example

DevOps-Team │ ├── linux-project ├── docker-project ├── kubernetes-project ├── terraform-project └── aws-project

Yahan DevOps-Team ek Group hai aur uske andar multiple Projects hain.

2. What is a GitLab Subgroup?

Large organizations mein ek group ke andar Subgroups create kiye ja sakte hain.

Subgroup ka purpose projects ko aur granular organizational structure mein divide karna hai.

Example

My-Company │ ├── DevOps │ ├── CI-CD │ │ ├── Jenkins │ │ └── GitLab-CI │ │ │ ├── Cloud │ │ ├── AWS │ │ └── Azure │ │ │ └── Kubernetes │ ├── Production │ └── Development │ └── Development ├── Frontend └── Backend

Is structure mein:

  • My-Company = Top-level Group
  • DevOps = Subgroup
  • CI-CD = Nested Subgroup
  • GitLab-CI = Project
DevOps Learning Tip: Small personal projects ke liye subgroup ki zarurat nahi hoti. Large team ya organization environment mein groups/subgroups ka concept important ho jata hai.

3. Group vs Project

Feature Group Project
Purpose Projects ko organize karna Actual code/repository manage karna
Contains Projects aur subgroups Repository, issues, CI/CD, settings etc.
Code Repository Directly repository nahi hota Yes
Example DevOps Team Docker Project
Remember:

Group organization ke liye hota hai.
Project actual software/code work ke liye hota hai.

15. Step 7 — Add GitLab Remote

Local Git repository ko GitLab repository ke saath connect karne ke liye remote add karte hain.

SSH Method

git remote add origin git@gitlab.com:USERNAME/PROJECT.git

Example

git remote add origin git@gitlab.com:pavan/terraform-aws.git

Check Remote

git remote -v

Expected pattern: 


origin  git@gitlab.com:USERNAME/PROJECT.git (fetch)
origin  git@gitlab.com:USERNAME/PROJECT.git (push)

16. Step 8 — Set Main Branch

Agar tum main branch use karna chahte ho:

Current branch check:

17. Step 9 — Push Code Using SSH

Agar GitLab SSH key configured hai:

git push -u origin main

Yahan:

  • git push = Local commits ko remote repository par bhejna.
  • -u = Upstream tracking set karna.
  • origin = Remote repository ka common name.
  • main = Push ki ja rahi branch.
First successful push ke baad future mein configured branch par aksar simple:

git push

use kiya ja sakta hai.

18. Push Code Using HTTPS

Agar repository HTTPS remote use kar rahi hai:

Authentication ke liye GitLab ki supported credential/token mechanism use karni hoti hai; normal account password ko Git over HTTPS authentication ke liye assume nahi karna chahiye.

Verify Remote

git remote -v

24. Common GitLab Push Errors

Error 1 — Permission denied (publickey)

git@gitlab.com: Permission denied (publickey).

Possible reasons:

  • SSH key GitLab mein add nahi hai.
  • SSH agent mein key loaded nahi hai.
  • Wrong SSH key use ho rahi hai.
  • Remote URL incorrect hai.

Test:

ssh -T git@gitlab.com

Error 2 — Remote already exists

error: remote origin already exists.

Check:

git remote -v

Remote URL change:

git remote set-url origin git@gitlab.com:USERNAME/PROJECT.git

Error 3 — Rejected Push

Agar remote repository mein already commits hain jo local repository mein nahi hain, push reject ho sakta hai.

git pull --rebase origin main

Conflicts aaye to unhe resolve karke commit/rebase complete karo aur phir push karo.

Error 4 — Wrong Repository

Push karne se pehle:

git remote -v
Good Habit: Push se pehle hamesha verify karo:

git status
git remote -v
git branch --show-current

25. Push ke Baad Pull/FETCH

Remote repository se latest changes lene ke liye:

git pull

Sirf remote changes download karke inspect karne ke liye:

git fetch
Command Purpose
git push Local commits ko remote par bhejna
git fetch Remote changes download karke local refs update karna
git pull Fetch ke baad current branch ke changes integrate karna

26. GitLab Push Security Rules

Never Push Secrets

  • AWS Access Keys
  • Cloud credentials
  • API keys
  • Database passwords
  • SSH private keys
  • JWT secrets
  • .env files containing secrets

Use .gitignore


.env
*.pem
*.key
.venv/
node_modules/
__pycache__/
Important: Sirf .gitignore add karna already committed secret ko automatically repository history se remove nahi karta. Agar secret accidentally commit ho gaya hai, credential ko immediately rotate/revoke karna aur history cleanup separately handle karna chahiye.
